# Motion renders

See [Motion design from screens](guide.md#motion-design-from-screens) for the basic command.

This mode turns saved screens into a film without recording. It requires `ffmpeg` and `ffprobe` on PATH and runs offline after ingest. The default HyperFrames engine uses the pinned pair described below; the legacy engine uses a sha256 and version pinned Linux x86_64 headless shell. Install the legacy shell with `takeone motion install-shell` (requires network access and `unzip` on PATH); `takeone doctor` reports its identity. Both installers use TakeOne's cache under `XDG_CACHE_HOME` or `~/.cache`. `TAKEONE_CHROME` can select an existing legacy shell, which must match both pins in [shell.ts](../src/motion/shell.ts).

**Engines.** `takeone motion` renders with **HyperFrames** by default (`hyperframes@0.8.200` + `chrome-headless-shell@156.0.8078.47`). Install that pair once with `takeone motion install-hyperframes` (network + npm; ~370 MB under `XDG_CACHE_HOME`/`~/.cache`). The adapter writes a self-contained project at `<take>/.motion/hyperframes/` — one `index.html`, a composition root, one scene layer per storyboard scene carrying `data-start`/`data-duration`/`data-track-index`, every font vendored under `assets/`, the pinned GSAP inlined, and no `file://` or network reference. Real footage is a first-class `<video>` layer (with `data-playback-start` for the window into its source) and the optional storyboard `audio` bed is one `<audio>` layer, so HyperFrames muxes it exactly once. The render fails unless the output is the requested width, height, fps, frame count and duration, and unless audio was muxed when the storyboard asked for it. `--engine legacy` keeps the previous in-repo renderer for one release; `takeone render <dir> --engine …` overrides the engine recorded in `render.json`. The legacy shell install and `TAKEONE_CHROME` are only needed for `--engine legacy` and `--stills`.

The three core patterns are `hero-reveal`, `zoom-tour`, and `end-card`, selected by the comma-separated `--pattern` flag; omitting it plans all three. A tour accepts `--region x,y,w,h[:caption][@SCREEN]`; each stop reserves a bounded smooth move and enough reading time, including the effective theme `min_shot`. Regions wider than 1100 CSS px split into two half stops so the settled close-up stays readable; tours end on their last stop and cut to the next beat. Close-up views anchor to the region top (wider views stay centred) so headers and card tops stay whole. HTML and URL screens capture at dsf 2, and region coords are CSS px. Regions on different screens produce separate tours; impossible scene durations are rejected. With no `--pattern` and three or more screens the planner builds a launch film instead: a `kinetic-type` title beat, each labelled screen announced by its own full-type beat ahead of a clean captionless tour, then the end card, with black and cream beats strictly alternating by scene order (`invert` swaps the theme background and text colours for one scene). `kinetic-type` is also plannable on its own for a single title beat. Launch extras: the first screen's announce beat also mounts a phone frame over a close-up crop of its own region beside the type, and with three or more labels the last announce beat becomes a `bento` recap grid of real cropped screen states whose three state tiles each wear their label pill (crops are aspect-fitted top-anchored region windows cut at ingest, so tiles never slice card tops). Settled tour close-ups and every phone or bento crop keep their planned framing when it is already whole; otherwise they move to the tightest framing of the same aspect, no narrower than planned, that keeps every detected field, button and card whole (or all but a sliver out of frame, as `make` allows) and runs no edge through a word. That can widen a close-up or shift a crop sideways. When no such framing exists, or a snapped tour needs longer than its planned duration, the planned framing stays and the run prints a warning. Announce beats carry the message copy: the subtitle on the first, the CTA after that. `--state NAME='click #id; type #id "text"; wait 100'` captures real HTML or URL states. States run in order in one page. Names must be unique, contain 1–64 letters, digits, underscores or hyphens, and must not be JavaScript integer-index keys (`0` through `4294967294`). The same restrictions apply to storyboard `source.states` keys; `__proto__` is a supported name. Semicolons inside quoted text are preserved. Tuple operations in storyboard JSON also support partial drag `["drag", "#card", "#lane", {"capture_at":0.6}]` followed by `["drop"]`. Timer waits use a deterministic page clock while Chromium continues painting. No desktop or phone is involved.

Screenshot sources (image files only) are still planned by the local rules: image planning is not enabled, so no screenshot is sent to a planner. Before using an image elsewhere, run `takeone motion screen.png --redaction-dry-run --out ./redaction-review`. This writes `screen-1.png` and `redaction-report.json` locally, then stops without planning, rendering or sending anything. The report records mask classes and pixel coordinates, never matched text or barcode contents. The original image remains untouched and is the source for the eventual film. This preview supports non-interlaced 8-bit RGB/RGBA PNG; it requires local Tesseract OCR and zbarimg. It masks whole OCR lines containing emails, phones, keys, tokens, account names, home paths or IP addresses, plus located QR/barcodes, with half-line-height padding. It repeats the same detectors on the redacted PNG up to three times. The report records every mask and residual hit (class, text length, coordinates, pass), not matched text. Any sensitive hit after three passes refuses the run and still writes the local report and preview; missing tools, unsupported images and invalid boxes also fail closed. Public site domains may be excluded from sensitive classification only with an explicit `--public-domain example.com` on this dry run; emails at that domain are still sensitive. OCR/barcode scanning cannot prove an image has no undetected secrets, especially faces, stylized text or undecodable codes. Review every pixel yourself; image transmission remains disabled. `--theme`, `--pattern` and `--region` fix the decisions they name, and `--no-ai` silences that warning. `--plan-only` writes an editable storyboard without ingest or rendering. Without `--out`, motion allocates a new timestamped take directory under the takes root, adding a numeric suffix on collisions; these takes appear in `takeone list`. `takeone render <dir>` rerenders the saved storyboard and source screens. Edit `storyboard.json` to change the film; the only render flags a motion take accepts are `--aspect landscape|portrait|square|4:5`, `--stills <seconds,...>` and `--engine hyperframes|legacy`. The HyperFrames engine currently rejects `--aspect`, `--stills` and frame-directory proofs, so use `--engine legacy` for those; a rerender otherwise follows the engine recorded in `render.json`. `--aspect` renders the same timeline at that frame size, re-laid out from the frame (never a crop), to `out/<id>-<w>x<h>.mp4` with `render-<w>x<h>.json`. `--stills` writes one PNG per film time to `out/<id>[-<w>x<h>]-<t>s.png` instead of the film, for contact sheets and critique passes. The first render ingests sources when the screen map is empty and saves that map for later rerenders. A supplied `--storyboard file.json` uses paths relative to the output take directory; use absolute source paths when importing a plan from elsewhere.

**Patterns and recipes.** `--pattern` also selects `logo-sting` (wordmark scale and tracking sting), `spotlight` (dim with a gliding hole and a label per `--region`), `feature-callouts` (2 to 5 labelled regions, numbered cards with an accent connector, then a numbered summary), `before-after` (two images, or two `--state` names; a wipe settling at a 50% split, `--subtitle` as its delta line) and `device-orbit` (a tilted device turning flat and floating). `--recipe launch|feature|social|compare` plans the approved sets from the same flags: launch = logo-sting + hero-reveal + zoom-tour (3 stops) + end-card; feature = hero-reveal + feature-callouts + end-card; social = kinetic-type + device-orbit + spotlight + end-card; compare = kinetic-type + before-after + end-card. `--aspect landscape|portrait|square` sets the output shape of any plan (portrait is 1080x1920; `social` defaults to it). Still to come from the approved library: scroll-through, split-compare, stack-cascade, cursor-story, highlight-reel.

**Existing take.** `takeone motion <take-dir> [--title TEXT] [--cta TEXT] [--url TEXT] [--out DIR]` turns a take you already have (a directory holding `take.json`) into an editable film: a title, the take's own footage played edge to edge, and a closing line. The footage is `out/<id>.mp4` (the rendered film) or else `screen.webm`; with neither the command stops and says to run `takeone make` first. Planning is local, with no planner and no network. The storyboard records `source: {kind: "take", dir}` and one clip, `clips.footage`, over the whole take (up to 120 s); edit its `start`, `d` or `crop`, the scene text or the order (the first render saves every scene's `at`, so change `at` along with `d`), and `takeone render <dir>` rerenders the edited storyboard with no planning at all.

**Editorial recipe.** `takeone motion <screenshot.png> --recipe editorial --pitch "what it does, in a few lines" [--logo WORD] [--cta TEXT] [--url TEXT] [--audio FILE]` is planned by the signed-in AI engine the same way `make` finds one (a signed-in Claude, Codex or OpenCode CLI, or a stored key); with none it exits 3 with one `takeone needs an AI engine` sign-in line and writes nothing, since there is no local plan to fall back to. TakeOne reads the screen's text lines with OCR and sends only the pitch and the redacted line words with their boxes, never the screenshot. The model writes every word and picks the lines each beat shows; TakeOne lays them on a 120 BPM grid with hard cuts in the `editorial` theme: `word-swap` (a serif hook whose last word is struck and swapped, the settled word selected under a cursor), `phone-story` (a phone-shaped crop of the screen rising on a phone shown whole, panned to the tapped control, pressed, a lens card beside it showing the tapped row at reading size, and a confirmation springing in; a tap line too long for the lens is asked again), `chip-stack` (the screen's own lines cut out as chips, one per beat, scaled to fill their side of the frame, the active one ringed in the accent sampled from the screen), `canon` (those three beats replayed in four tiles on staggered clocks), a `statement` payoff and the end card. One warm accent runs through the film as a motif (the rule under the side copy, the strike line, the lens border, the tap ring): the screen's own commonest warm hue when it has one, otherwise orange-red. A broken field is asked again once, with what it broke; a second miss stops and names the field. The written `storyboard.json` rerenders like any other.

**Model-made segments.** `takeone motion film <video.mp4> [--intro BRIEF] [--callout "BRIEF@SECONDS"]... [--outro BRIEF] [--tech html|canvas|three]` frames a real recording with motion segments the signed-in AI engine writes (the same engine discovery as `make`; with none it exits 3 with the sign-in line and writes nothing). Each segment is one offline HTML page (DOM and CSS, SVG, a 2D canvas or Three.js r149, which the renderer loads as the global `THREE`). Only the briefs go to the engine, never the video. The film is the footage at its own size (long edge at most 1920 px), untouched, with a 3 s `segment` scene before it (`--intro`), after it (`--outro`), and in between where `--callout` cuts it at a time in seconds (the footage resumes where it left off). A `.html` path in place of a brief is used as written, so a page you or any agent wrote needs no engine. `--tech` tells the model which technique to use and defaults to `html`.

A segment is declared in a storyboard as `segments:{id:{file,d}}` and played by `{pattern:"segment",segment:id,d}` scenes (HyperFrames engine only; `d` at most the segment's). The page's contract: it defines `window.takeoneSegment = {seek(t)}`, where `t` runs from 0 to `d` seconds and `seek` draws the whole frame as a pure function of `t` (no timers, rAF loop, clock or state carried between calls); it may set `window.takeoneReady` to a promise for its assets. It is self-contained and sized from `innerWidth`/`innerHeight`. The page is untrusted code, so it only ever runs in the pinned headless shell with the network off: a fetch fails the render naming the URL, a thrown error names its time, and `Math.random` restarts on every seek so noise is the same on every run. Ingest renders each stale segment at the film's size and 60 fps to `sources/segments/<id>.mp4` (re-rendered only when the page, length, size or preset changes) and refuses any frame where a DOM text element that is shown (opacity above 2%) leaves the frame's 5% inset, so words are never cut or slid in from outside the frame; text painted on a canvas is not checked, so keep it inside the same inset. Each scene still must open and end on picture (the per-scene cut check). A model that breaks the contract is asked again once, with what it broke; a second miss stops, naming the page it kept. Example pages are in [resources/demo/segments/](../resources/demo/segments/).

**Bento recipe.** `takeone motion <screenshot.png> --recipe bento --pitch "…" [--logo WORD] [--cta TEXT] [--url TEXT] [--audio FILE]` is planned the same way (signed-in engine, redacted line words and boxes only, exit 3 with the sign-in line when there is none). The model writes the headline and its highlighted last words, a counter label and demo figure, 4 to 6 feed rows, the payoff and the CTA, and picks 2 or 3 screen lines; TakeOne cuts a crop of the real screen around each. One 12 s `bento-reel` scene lays five tiles on a 12×6 grid that reflows at 4 s and 8 s (a spring per tile, 30 ms stagger, 0.4 s, content re-laid out and never stretched): the serif headline with an inverted highlight wipe, procedural SVG op-art (stripes, zigzag, checks) that swaps on the beat, a counter rolling to the demo figure with a line chart drawing, a LIVE feed whose inserts push older rows down, and the real crops. A `statement` payoff and the end card follow. Figures and feed rows are demo content and are not claimed as real. Not yet in the recipe: the exit where tiles fly out and a disc grows to the frame, end-card stickers, map pings, receipts and the theme carousel.

Storyboard v1 contains `source`, `screens`, `regions`, `scenes`, `output`, `theme`, optional `clips` and optional `audio`; field definitions are owned by [types.ts](../src/motion/types.ts) and validation by [storyboard.ts](../src/motion/storyboard.ts). Scene `at` defaults to the previous scene end; nonnegative, nonoverlapping scene windows define cuts. Text duration includes its reveal and a full reading hold in the effective visible window, including default fragment copy and the counter's final value. Output defaults to 1920×1080 at 60 fps with eight workers; `--workers N` selects an integer from 1 to 64. Storyboard output dimensions can be overridden with even integers for bento master comparisons; fps stays fixed. Worker count is part of the render identity: keep it fixed between deterministic rerenders. HyperFrames rerenders are not bit-exact, so determinism is checked with a stated tolerance: `node scripts/motion-determinism.ts a.mp4 b.mp4` passes two renders of one storyboard when they have the same frames and every frame is within 50 dB PSNR (average of Y, U and V) of its twin. Two renders of a 23 s, 1377-frame launch film differed on 180 frames, lowest 57.37 dB; the check makes no comparison with the legacy engine. `render.json` records the engine and, for the legacy path, workers, shell, encoder, timing and subframe accumulation; the HyperFrames path records the engine pack and browser pair. Hero and tour bitmap transforms also write `camera.json`.

`layout: {kind:"bento", grid:"2x2", master:{d:6,scenes:[...]}, tiles:[{id:"TL",offset_s:0},...]}` plays the same master in four clipped viewports with shifted clocks. Tile ids are TL, TR, BL and BR; each tile plays master time `film time + offset_s`, and `master.d` sets the output duration. The validator checks reading holds in each intersecting tile window, from `offset_s` through `offset_s + master.d`; offsets or durations that truncate required reading time are rejected. Zoom tours must fit entirely within each intersecting visible window. `pinwheel-3x2` instead takes `tiles:{A:[...],B:[...],C:[...],D:[...]}` for independent timelines. Gutters, page colour and corners are theme tokens.

`tempo:{bpm:120,phase_s:0,snap:"beat"}` requires scene boundaries on half-second beats. One frame of drift is snapped; larger drift is rejected. `snap:"half"` permits quarter-second boundaries. Bento `2x2` offsets also snap or reject on the grid, with zero phase for offsets.

Real footage: top-level `clips:{id:{files:[...],start,d}}` names windows of real video (a raw capture, or TakeOne's own renders of it). The first render cuts each file's window into 60 fps frames under `sources/clips/` and saves them as `frames`; editing a clip's `files`, `start`, `d` or `crop` re-cuts that clip on the next render, and frames deleted from disk are reported as missing ingest rather than failing at decode; an optional `crop` list gives one ffmpeg `w:h:x:y` crop (or null) per file, cutting the real frame down to its subject. List one file per format (for example a take rendered with `--aspect landscape`, `portrait` and `square`): each output size plays the file whose own (uncropped) aspect is nearest its own, so a 9:16 film shows the 9:16 re-aim. A `clip` scene plays `clip` in a window fitted to the frame, scaled by `scale` (default 1; a window never grows past its margins, so above 1 changes nothing) and springing in from `from`. A typed mono `label` rides above the window's top-left corner. `fill:true` (HyperFrames only) plays the footage edge to edge instead, so the product is the frame rather than an inset; its `label` sits on an ink chip inside the 5% inset at a twentieth of the frame's short side, so it reads on a phone, and leaves after its reading time (at least 2 s) so it stops covering the page. The chip takes the first of six corner and edge spots, and the earliest moment, where the decoded footage shows no page text under it for that reading time; when text crosses every spot the clip plays in a fitted window with its label above it instead, and the render warns. `cuts:[{at,clip?,label?,scale?}]` retarget the window mid-scene, adding one spring per change, or swap the footage, which is a hard cut to a new shot, and may swap the label; every label keeps its reading time before the next cut. A `statement` scene sets a centred display `title` (required, non-empty) whose words rise and fade in, an optional `subtitle` and a mono `note` on the bare page. Motion uses closed-form springs (`track` in [runtime.js](../resources/motion/runtime.js)): a hair of overshoot on UI, none on type. A seek waits for every clip frame to decode, so each frame is still a pure function of time. Scenes settle in from a 4% push over their first half second, drawn whole from their first frame (never faded up from bare background), unless `cut:true` keeps the hard cut on the beat. Safe area: clip windows and labels are laid out inside the frame's 5% inset, with room for the UI spring's overshoot. Every render, and every `--stills` run, first checks the statement titles, subtitles and notes, the clip labels and the footage windows at each frame it will draw. It measures them in their scene layer, so the push-in is not judged. It also lists every shown word that a clipping box (an `overflow` other than visible) cuts part-way, so a title that slides up through a mask is caught on the frames where it is half drawn. When any of them crosses the 5% inset or is cut, the render exits 1 before drawing, naming the first box, and lists every box in `safe-area[-WxH].json`. Title, statement and hero type reveal whole words (each rises 0.3 em and fades in, never through a mask), and each reveal starts 150 ms early, so a scene's first frame, a cut point, already shows its first word. Text inside the footage is checked by the take's own render (see [headless-scene.md](headless-scene.md#safe-area)). An optional top-level `audio:{file,start?,volume?}` names one music or SFX bed. The HyperFrames engine copies it into the project and muxes it once; the legacy engine rejects it rather than dropping the sound. After a HyperFrames render the film is also cut into one file per scene, `out/scenes/NN-<title>.mp4`, on the scenes' exact frames; the render fails when a scene file's first or last frame is blank (one flat colour), since a cut-ready clip opens and ends on picture. Before the cuts, the film itself is gated on frozen time and, when it has an audio bed, on loudness (`gates` in `render.json`, adapted from motion-video-kit, see [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md)). Frozen time samples the film at 10 fps, 320 px grey, and calls a sample frozen when its luma difference from the last is under 0.35; the end-card scenes are the only allowed holds. The render warns on stderr, naming the frozen spans and recording `passed: false`, when any other still stretch lasts over 0.6 s or (for films of 10 s or more) totals over 1 s per 30 s; it does not fail. Held shots are never still: `logo-sting`, `hero-reveal` and `zoom-tour` move their subject round a small circle at constant speed (`drift` in [runtime.js](../resources/motion/runtime.js): 0.7% of the frame width in radius, one lap every 3 s), so the frame and every word in it move together and no word nears an edge. On the Tidewater board the `launch` recipe measured 5.8 s longest frozen and 17.9 s per 30 s before the change, and 0 s and 0 s after. Loudness uses ebur128 on the muxed bed and fails when the integrated level is outside -19..-14 LUFS or the true peak is above -1 dBTP; lower or raise `audio.volume`. A silent bed fails too. `out/scenes.json` lists each scene's file, start, end, title, pattern and frame count for an editor. The demo film's storyboard is [resources/demo/film/storyboard.json](../resources/demo/film/storyboard.json).

Motion pages reject CSS gradients; use SVG gradients or patterns. Fonts are bundled with SHA entries and OFL licenses. The `editorial` theme uses the bundled Instrument Serif display face. The font cmap coverage gate checks storyboard copy and emitted fragment/device text in their actual font roles, including the default end-card wordmark and chrome mounted by hero and tour scenes. Chrome symbols and the toast checkmark use fixed bundled symbol faces defined in [theme.ts](../src/motion/theme.ts); text-role overrides do not change those faces. Missing glyphs reject the plan, so select a bundled font with coverage. End-card letters animate whole grapheme clusters at measured kerned positions, keeping combining marks attached. The fragment pattern accepts `kind`: button, input, chip, toast, feed-row, counter, line-chart, bar-chart, spinner, browser-chrome, phone-chrome; button states are idle/hover/pressed, input states empty/typing/filled. Fragments inherit theme tokens and an accent sampled deterministically from the first screen. Image sources are copied unchanged; palette sampling decodes them locally through ffmpeg, including indexed, greyscale, non-8-bit and interlaced PNGs and JPEGs.

Motion blur is enabled by default and accumulates subframes only above 35 output pixels per frame. The schedule uses eight samples normally and at least 24 around the fastest half-second, increasing sample count when needed to keep spacing within two pixels. `--blur 0` disables accumulation. Faster spans cost extra captures; the manifest reports the actual cost and peak spacing.

Offline proof gates compare the encode to lossless frames from the same render settings, require VMAF ≥95, and stop for human review if any frame has SSIM <0.95. They also check moving-camera duplicates and a rendered SVG smooth-ramp fixture for flat runs ≤64 pixels. The six-second timing proof fails above 15 seconds. Regenerate proofs after renderer changes.

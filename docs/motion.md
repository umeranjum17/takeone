# Motion renders

See [Motion design from screens](../README.md#motion-design-from-screens) for the basic command.

This mode turns saved screens into a film without recording. It requires `ffmpeg` and `ffprobe` on PATH and runs offline after ingest, with a sha256 and version pinned Linux x86_64 headless shell. Install the shell with `takeone motion install-shell` (requires network access and `unzip` on PATH); `takeone doctor` reports its identity. The installer uses TakeOne's cache under `XDG_CACHE_HOME` or `~/.cache`. `TAKEONE_CHROME` can select an existing shell, which must match both pins in [shell.ts](../src/motion/shell.ts).

The three core patterns are `hero-reveal`, `zoom-tour`, and `end-card`, selected by the comma-separated `--pattern` flag; omitting it plans all three. A tour accepts `--region x,y,w,h[:caption][@SCREEN]`; each stop reserves a bounded smooth move and enough reading time, including the effective theme `min_shot`. Regions wider than 1100 CSS px split into two half stops so the settled close-up stays readable; tours end on their last stop and cut to the next beat. Close-up views anchor to the region top (wider views stay centred) so headers and card tops stay whole. HTML and URL screens capture at dsf 2, and region coords are CSS px. Regions on different screens produce separate tours; impossible scene durations are rejected. With no `--pattern` and three or more screens the planner builds a launch film instead: a `kinetic-type` title beat, each labelled screen announced by its own full-type beat ahead of a clean captionless tour, then the end card, with black and cream beats strictly alternating by scene order (`invert` swaps the theme background and text colours for one scene). `kinetic-type` is also plannable on its own for a single title beat. Launch extras: the first screen's announce beat also mounts a phone frame over a close-up crop of its own region beside the type, and with three or more labels the last announce beat becomes a `bento` recap grid of real cropped screen states with label pills (crops are aspect-fitted top-anchored region windows cut at ingest, so tiles never slice card tops). Announce beats carry the message copy: the subtitle on the first, the CTA after that. `--state NAME='click #id; type #id "text"; wait 100'` captures real HTML or URL states. States run in order in one page. Names must be unique, contain 1–64 letters, digits, underscores or hyphens, and must not be JavaScript integer-index keys (`0` through `4294967294`). The same restrictions apply to storyboard `source.states` keys; `__proto__` is a supported name. Semicolons inside quoted text are preserved. Tuple operations in storyboard JSON also support partial drag `["drag", "#card", "#lane", {"capture_at":0.6}]` followed by `["drop"]`. Timer waits use a deterministic page clock while Chromium continues painting. No desktop or phone is involved.

`--plan-only` writes an editable storyboard without ingest or rendering. Without `--out`, motion allocates a new timestamped take directory under the takes root, adding a numeric suffix on collisions; these takes appear in `takeone list`. `takeone render <dir>` rerenders the saved storyboard and source screens; motion takes reject additional render flags, so edit `storyboard.json` to change their settings. The first render ingests sources when the screen map is empty and saves that map for later rerenders. A supplied `--storyboard file.json` uses paths relative to the output take directory; use absolute source paths when importing a plan from elsewhere.

Storyboard v1 contains `source`, `screens`, `regions`, `scenes`, `output`, and `theme`; field definitions are owned by [types.ts](../src/motion/types.ts) and validation by [storyboard.ts](../src/motion/storyboard.ts). Scene `at` defaults to the previous scene end; nonnegative, nonoverlapping scene windows define cuts. Text duration includes its reveal and a full reading hold in the effective visible window, including default fragment copy and the counter's final value. Output defaults to 1920×1080 at 60 fps with eight workers; `--workers N` selects an integer from 1 to 64. Storyboard output dimensions can be overridden with even integers for bento master comparisons; fps stays fixed. Worker count is part of the render identity: keep it fixed between deterministic rerenders. `render.json` records workers, shell, encoder, timing and subframe accumulation. Hero and tour bitmap transforms also write `camera.json`.

`layout: {kind:"bento", grid:"2x2", master:{d:6,scenes:[...]}, tiles:[{id:"TL",offset_s:0},...]}` plays the same master in four clipped viewports with shifted clocks. Tile ids are TL, TR, BL and BR; each tile plays master time `film time + offset_s`, and `master.d` sets the output duration. The validator checks reading holds in each intersecting tile window, from `offset_s` through `offset_s + master.d`; offsets or durations that truncate required reading time are rejected. Zoom tours must fit entirely within each intersecting visible window. `pinwheel-3x2` instead takes `tiles:{A:[...],B:[...],C:[...],D:[...]}` for independent timelines. Gutters, page colour and corners are theme tokens.

`tempo:{bpm:120,phase_s:0,snap:"beat"}` requires scene boundaries on half-second beats. One frame of drift is snapped; larger drift is rejected. `snap:"half"` permits quarter-second boundaries. Bento `2x2` offsets also snap or reject on the grid, with zero phase for offsets.

Motion pages reject CSS gradients; use SVG gradients or patterns. Fonts are bundled with SHA entries and OFL licenses. The `editorial` theme uses the bundled Instrument Serif display face. The font cmap coverage gate checks storyboard copy and emitted fragment/device text in their actual font roles, including the default end-card wordmark and chrome mounted by hero and tour scenes. Chrome symbols and the toast checkmark use fixed bundled symbol faces defined in [theme.ts](../src/motion/theme.ts); text-role overrides do not change those faces. Missing glyphs reject the plan, so select a bundled font with coverage. End-card letters animate whole grapheme clusters at measured kerned positions, keeping combining marks attached. The fragment pattern accepts `kind`: button, input, chip, toast, feed-row, counter, line-chart, bar-chart, spinner, browser-chrome, phone-chrome; button states are idle/hover/pressed, input states empty/typing/filled. Fragments inherit theme tokens and an accent sampled deterministically from the first screen. Image sources are copied unchanged; palette sampling decodes them locally through ffmpeg, including indexed, greyscale, non-8-bit and interlaced PNGs and JPEGs.

Motion blur is enabled by default and accumulates subframes only above 35 output pixels per frame. The schedule uses eight samples normally and at least 24 around the fastest half-second, increasing sample count when needed to keep spacing within two pixels. `--blur 0` disables accumulation. Faster spans cost extra captures; the manifest reports the actual cost and peak spacing.

Offline proof gates compare the encode to lossless frames from the same render settings, require VMAF ≥95, and stop for human review if any frame has SSIM <0.95. They also check moving-camera duplicates and a rendered SVG smooth-ramp fixture for flat runs ≤64 pixels. The six-second timing proof fails above 15 seconds. Regenerate proofs after renderer changes.
